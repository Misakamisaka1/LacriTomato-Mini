Design Review Draft - 2026-06-17

LacriTomato Mini 桌面宠物工具

目标不是只做一个简单 Electron 小工具，而是做一个 Windows 桌宠平台。 第一版落地翻译和截图/OCR，同时用插件架构承接未来聊天、宠物情绪、行为脚本、贴图、滚动截图等能力。

当前素材为 spritesheet.webp 和 pet.json。 spritesheet 尺寸约为 1536 x 1872，看起来接近 8 列 x 9 行、每格 192px 的动画图集。

Windows first Electron + TypeScript Plugin platform OpenAI-compatible models
LacriTomato Mini spritesheet

1. 项目摘要

第一版应用启动后，桌面显示 LacriTomato Mini 宠物。 用户右键宠物后，不显示传统系统菜单，而是在宠物头顶弹出动画功能菜单。 功能模块像手风琴/钢琴琴键一样依次展开，可以进入翻译、截图、截图 OCR、贴图管理、设置等功能。 设置页用于配置模型服务、API Key、快捷键、截图行为、OCR 模式、宠物行为和插件开关。

应用需要长期可维护，所以采用插件化平台架构。 第一版先内置 translator 和 screenshot 两个插件。 插件接口从一开始存在，但先不支持安装外部不可信插件，避免第一版陷入安全、签名和动态加载复杂度。

产品定位

一个有生命感的桌面宠物入口，承载翻译、截图、OCR、贴图、聊天等桌面辅助能力。

第一版重点

稳定桌宠窗口、翻译面板、截图编辑、OCR、设置页、插件注册和快捷键系统。

长期方向

升级为带宠物聊天、情绪状态、行为脚本、桌面任务助手和插件扩展的桌宠平台。

3. 总体架构

Electron 主进程掌管所有原生能力：窗口、托盘、全局快捷键、屏幕捕获、剪贴板、文件保存和安全配置。 Renderer 只负责 UI。 Preload 暴露一层受控、类型化 API，禁止 UI 直接访问 Node 或 API Key。 

Electron Main
  app lifecycle, tray, globalShortcut, desktopCapturer, native windows
  services: config, shortcut, model, screenshot, OCR, plugin registry

Preload Bridge
  typed API exposed to renderer
  no direct Node access from renderer

Renderer Shell
  PetApp, SettingsApp, floating panels

Plugins
  translator, screenshot, future chat, future pet interactions

核心服务

pluginRegistry

加载内置插件 manifest，收集菜单、快捷键、设置区域、窗口面板和 IPC 能力。

configService

管理普通配置和安全配置。API Key 使用 Electron safeStorage 加密。

modelService

统一封装 OpenAI-compatible text/vision 请求，翻译和未来聊天共用。

screenshotService

处理屏幕源、DPI 坐标、裁剪、保存、剪贴板和窗口隐藏策略。

ocrService

第一版本地 OCR，未来支持模型 OCR。对上层只暴露统一 recognize 接口。

petBehaviorService

管理宠物状态、动作、气泡、空闲行为和未来聊天驱动动作。

4. 窗口与交互设计

应用包含多类窗口，每类窗口职责单一。 桌宠窗口负责陪伴和入口，设置窗口负责配置，翻译和截图作为插件面板或专用窗口出现。 功能入口不采用传统右键菜单列表，而是使用宠物头顶的动画功能菜单，强化桌宠工具的角色感。

PetWindow
透明无边框桌宠窗口
TranslatorPanel
ScreenshotOverlay
SettingsWindow

窗口列表

窗口 职责 关键行为
PetWindow 显示桌宠、承载头顶动画功能菜单、气泡和入口。 透明、无边框、置顶、可拖拽、任务栏隐藏。
SettingsWindow 配置模型、快捷键、截图、OCR、宠物和插件。 普通窗口，可从托盘或头顶功能菜单打开。
TranslatorPanel 翻译输入、语言选择、结果展示、历史记录。 浮动面板，可贴近宠物弹出，也可独立移动。
ScreenshotOverlayWindow 全屏框选、标注和截图编辑。 按显示器创建 overlay，处理 DPI 和负坐标。
PinnedImageWindow 贴图钉在桌面。 无边框、置顶、可拖拽缩放、右键关闭。

宠物头顶动画功能菜单

右键宠物后，PetWindow 内部渲染一个自定义功能菜单。 菜单锚定在宠物头顶，功能模块从下往上或沿轻微弧线依次弹出。 动画感觉接近手风琴/钢琴琴键：每个模块像一片功能键，依次展开，悬停时放大并显示功能说明。 

右键宠物
  -> 宠物暂停移动，进入 attentive 状态
  -> 功能键依次弹出
      翻译
      截图
      截图并 OCR
      贴图管理
      和我聊天 (Coming soon)
      设置
      隐藏宠物
      退出
  -> 点击功能键
      执行插件 action 或打开窗口
  -> 点击空白处 / Esc
      菜单收起，宠物恢复原状态

动画菜单交互细节

  • 菜单由插件 manifest 的 menuItems 贡献，但渲染方式由平台统一控制。
  • 菜单默认锚定在宠物头顶；如果靠近屏幕边缘，自动翻转到左侧、右侧或下方，避免超出屏幕。
  • 每个功能键使用图标、短标题和颜色标识；悬停时展开副标题。
  • 弹出动画使用 stagger 延迟，形成一格一格展开的节奏。
  • 点击禁用或未完成的功能，例如“和我聊天”，显示宠物气泡提示。
  • 仍保留托盘菜单作为兜底入口，避免用户在宠物隐藏时无法操作。

5. 插件系统设计

采用“受控内置插件”作为第一阶段。 每个插件声明自己的菜单项、快捷键、设置区、面板和能力。 平台负责注册、渲染入口和代理 IPC。 

interface PetdexPluginManifest {
  id: string;
  name: string;
  version: string;
  menuItems: PluginMenuItem[];
  shortcuts?: PluginShortcutContribution[];
  settingsSections?: PluginSettingsSection[];
  panels?: PluginPanelContribution[];
  capabilities: PluginCapability[];
}

贡献点

贡献点 说明 示例
menuItems 向宠物头顶动画菜单或托盘菜单添加入口。 翻译、截图、截图并 OCR。
shortcuts 声明默认快捷键和配置项。 captureArea, quickTranslate。
settingsSections 向设置页添加插件配置区域。 截图保存目录、OCR 语言、翻译历史。
panels 声明插件的 UI 面板或窗口。 TranslatorPanel, ScreenshotEditor。
capabilities 声明需要的平台能力，方便安全审计。 model:text, screen:capture, clipboard:image。
第一版不开放任意第三方插件代码执行。 外部插件市场可以后续做，但需要额外设计签名、权限提示、沙箱和升级机制。

6. 翻译插件设计

翻译插件接入通用模型服务，支持自定义 baseURL、model、apiKey。 默认模型名可以填 deepseek-flash，但代码不绑定某一家平台。 

interface TranslateRequest {
  sourceText: string;
  sourceLanguage: "auto" | string;
  targetLanguages: string[];
  style: "accurate" | "natural" | "concise";
}
interface TranslateResult {
  detectedLanguage?: string;
  results: Array<{
    language: string;
    text: string;
  }>;
  usage?: {
    promptTokens?: number;
    completionTokens?: number;
  };
}

UI 功能

  • 左侧源语言：自动检测、中文、英文、日文、韩文、法文、德文、西班牙文等。
  • 右侧目标语言：多选，可以一次翻译到多种语言。
  • 输入区支持粘贴、清空、字数统计。
  • 结果区按目标语言分块展示，每块支持复制、替换输入、继续翻译。
  • 历史记录本地保存最近 20 条，可在设置里关闭。
  • OCR 结果可以一键送入翻译插件。

模型调用策略

多目标语言翻译优先使用一次请求完成，并要求模型返回 JSON。 如果返回不是合法 JSON，系统显示原始响应并提示用户调整 prompt 或重试。 

{
  "detectedLanguage": "zh-CN",
  "translations": {
    "en": "Translated text",
    "ja": "Translated text",
    "ko": "Translated text"
  }
}

选中文字快捷翻译预留

全局快捷键触发。
主进程模拟 Ctrl+C 或读取剪贴板文本。
打开 TranslatorPanel，填入选中文本。
用户确认翻译，或者根据设置自动翻译。

7. 截图插件设计

截图插件负责全局快捷键、屏幕捕获、框选、标注、复制、保存、OCR 和贴图。 技术上使用 Electron desktopCapturer 与 screen API。

截图流程

用户按下截图快捷键。
隐藏宠物窗口，避免宠物被截进去。这个行为可在设置里关闭。
为每个显示器创建 ScreenshotOverlayWindow。
用户拖拽框选区域。
裁剪图像并进入编辑状态。
用户复制、保存、OCR、钉图或取消。

截图编辑能力

  • 矩形、箭头、画笔、文字、马赛克。
  • 撤销、重做、清空标注。
  • 复制到剪贴板。
  • 保存到默认截图目录。
  • OCR 识别后复制或发送到翻译。
  • 钉图到桌面。

标注数据结构

type Annotation =
  | { type: "rect"; x: number; y: number; w: number; h: number; color: string }
  | { type: "arrow"; from: Point; to: Point; color: string }
  | { type: "pen"; points: Point[]; color: string; size: number }
  | { type: "text"; x: number; y: number; text: string; color: string }
  | { type: "mosaic"; rect: Rect; size: number };

OCR

第一版使用本地 OCR，选择 Tesseract.js。默认语言为 chi_sim 和 eng。 OCR 服务暴露统一接口，未来可以切到模型 OCR。 

recognize(image, {
  mode: "local" | "model",
  languages: ["chi_sim", "eng"]
})

贴图

点击“钉住”后创建 PinnedImageWindow。 贴图窗口无边框、置顶、可拖拽、可缩放，右键菜单支持关闭、保存、调整透明度。

滚动截图

预留 startScrollingCapture() 接口和菜单入口。 第一版可标记为实验功能，不作为必须完成项。

8. 桌宠行为系统

用户选择完整桌宠方向，所以桌宠本体需要有状态、动作和未来聊天联动能力。 但第一版不做复杂养成数值，先做轻量行为系统。

素材 manifest

当前 pet.json 只有基础描述，需要扩展成动画 manifest。 如果确认 spritesheet 是 8 x 9，每格 192px，可以这样定义： 

{
  "id": "lacritomato-mini",
  "displayName": "LacriTomato Mini",
  "spritesheetPath": "spritesheet.webp",
  "frameWidth": 192,
  "frameHeight": 208,
  "columns": 8,
  "rows": 9,
  "animations": {
    "idle": { "frames": [0, 1, 2, 3, 4, 5], "fps": 6, "loop": true },
    "walkRight": { "frames": [8, 9, 10, 11, 12, 13, 14, 15], "fps": 9, "loop": true },
    "walkLeft": { "frames": [16, 17, 18, 19, 20, 21, 22, 23], "fps": 9, "loop": true },
    "happy": { "frames": [24, 25, 26, 27], "fps": 6, "loop": false },
    "sleepy": { "frames": [40, 41, 42, 43], "fps": 4, "loop": true }
  }
}

状态机

idle
  -> wandering
  -> thinking
  -> happy
  -> sleepy
  -> talking (future)
  -> reacting (future)

第一版行为

  • 空闲时播放 idle 动画。
  • 偶尔在屏幕底部小范围移动，可在设置里关闭。
  • 打开翻译或截图时显示 thinking 状态。
  • 翻译成功、OCR 成功时显示 happy 状态。
  • 发生错误时显示短气泡提示。
  • 鼠标悬停或头顶功能菜单展开时暂停移动，避免影响点击。

未来聊天联动

聊天插件以后可以向 petBehaviorService 发事件。 例如模型回复时进入 talking 状态，用户夸奖时进入 happy 状态，长时间未互动进入 sleepy 状态。

9. 设置与配置

设置页按侧边栏分组，避免所有选项堆在一个页面。 每个插件可以贡献自己的设置区，但核心设置统一在平台层管理。

设置分组 配置项
模型 baseURL、model、apiKey、temperature、timeout、测试连接、翻译 prompt。
快捷键 截图、截图 OCR、打开翻译、选中文字翻译、显示/隐藏宠物。
截图 保存目录、文件名格式、截图时隐藏宠物、复制格式、标注默认颜色。
OCR 本地/模型模式、语言包、识别后动作、发送到翻译。
桌宠 缩放、透明度、置顶、移动范围、动画速度、气泡开关。
插件 启用/禁用内置插件，查看插件能力。

配置文件位置

%APPDATA%/LacriTomato Mini/config.json
%APPDATA%/LacriTomato Mini/secure.json
%APPDATA%/LacriTomato Mini/screenshots/

config.json 存普通配置。 secure.json 存加密后的 API Key。 如果 Electron safeStorage 不可用，设置页需要提示“本机弱加密存储”。

10. 安全边界

因为应用会处理 API Key、截图和剪贴板，所以安全边界必须从第一版就明确。

  • Renderer 禁止直接访问 Node。
  • 所有敏感动作走 Preload 的 typed API。
  • API Key 不进入 Renderer 状态，也不写入日志。
  • IPC channel 使用白名单，不开放任意 invoke。
  • 截图和 OCR 结果默认只保存在本地。
  • 模型 OCR 或未来视觉模型必须明确提示会上传图片。
  • 插件第一版只允许内置受控插件，不执行外部插件代码。

IPC 命名示例

core:config:get
core:config:set
core:shortcut:register
core:model:translate
core:ocr:recognize
plugin:translator:translate
plugin:screenshot:startCapture
plugin:screenshot:saveCapture

13. 第一版验收标准

桌宠

  • 打开应用后宠物显示在桌面上，没有普通窗口边框。
  • 宠物可拖拽，右键能在宠物头顶打开动画功能菜单。
  • 宠物动画正常播放，透明背景正常。
  • 托盘菜单可以显示/隐藏宠物、打开设置、退出。

翻译

  • 设置页可以保存 baseURL、model、apiKey。
  • 翻译面板可以输入文本并翻译到多个目标语言。
  • 错误状态有明确提示，不泄露 API Key。
  • 翻译历史可查看，也可关闭。

截图

  • 快捷键能唤起截图 overlay。
  • 可以框选区域并进入编辑工具栏。
  • 支持矩形、箭头、画笔、文字、马赛克、撤销。
  • 可以复制到剪贴板和保存到文件。
  • 支持本地 OCR，结果可复制或发送到翻译。
  • 支持将截图钉在桌面。

可维护性

  • 翻译和截图都通过插件 manifest 注册菜单、设置和快捷键。
  • Renderer 不直接访问 Node 或 API Key。
  • 核心 services 有单元测试。
  • 主要窗口至少有一次手动或自动化冒烟测试。

14. 已采用默认决策

下面这些体验细节采用推荐方案，作为第一版默认配置。 后续都可以在设置页调整。

  1. 宠物默认大小：先用 224px 高度，设置页可调整缩放。
  2. 截图默认快捷键：Ctrl+Shift+A，OCR 截图用 Ctrl+Shift+O。
  3. 翻译默认目标语言：中文、英文、日文三组常用预设。
  4. OCR 默认语言包：中文简体和英文。
  5. 滚动截图：第一版作为实验入口，不纳入硬验收。
  6. 贴图：第一版做基础钉图，透明度和缩放右键菜单后续细化。
  7. 聊天功能：不进入第一版，但保留模型服务和宠物行为事件接口。

15. 推荐实施结论

采用插件化平台方案。 先用内置受控插件完成翻译和截图，避免第一版过早开放外部插件带来的安全与打包成本。 所有原生能力由主进程服务层托管，UI 只通过 typed preload API 访问。 桌宠从第一版起拥有状态机和动画 manifest，为后续聊天与互动能力做准备。
